## Context

Implementing `docs/plan/0002-text-extraction-plan.md` surfaced a few details the plan did
not pin down, plus two small safety additions. None changes the API contract, the error
codes, the table or the PRD's decisions D1-D9.

## Decision

1. **The "no text" check runs on the page texts, not on the joined text.** Joined text
   always contains the `--- Page N ---` markers, so it is never empty for a multi-page
   file. `extract_text` raises `no_text_found` when every page text is blank after `strip()`
   (the plan's "result text is empty").
2. **`_render_pages` returns prepared JPEG bytes**, calling `_prepare_image` per page inside
   the loop, instead of returning PIL images for a second pass. At most one full-size
   rendered page is in memory at a time.
3. **Render size guard (addition).** The render scale is `min(RENDER_DPI / 72,
   MAX_RENDER_SIDE / longest_page_side)` with `MAX_RENDER_SIDE = 4096`. A normal page
   (A4/Letter at 200 DPI is about 2300 px) is unaffected; a PDF with an absurd page size can
   no longer allocate a gigantic bitmap (Pillow's decompression-bomb guard only covers
   `Image.open`, not pypdfium2 output).
4. **Transparency is flattened onto white (addition).** `_prepare_image` composites
   RGBA / LA / palette-with-transparency images onto a white background before converting to
   RGB. Plain `convert("RGB")` turns transparent pixels black, which would hide black text
   in screenshot-style PNGs.
5. **`crud.upsert` re-reads the row itself on `ON CONFLICT DO NOTHING`** and always returns a
   row; the plan placed that re-read in the service. Same behaviour, one fewer branch in the
   service.
6. **Private helper layout.** Besides the helpers the plan lists, `service.py` has
   `_read_text_layer`, `_extract_pdf`, `_extract_image`, `_to_rgb` and a small frozen
   `_Extraction` dataclass (pages, method, page_count, model). `_transcribe_pages` takes
   `(llm, images, page_count)` and returns `(page_texts, model)`. The file is 279 lines, so
   the planned `_pdf.py` / `_images.py` split was not needed.
7. **`page_prompt(*, page, total)` is keyword-only and `total` is the real page count**, so a
   capped 7-page scan is prompted "page 5 of 7", not "page 5 of 5".
8. **`TextExtractionError` defaults to `unreadable_document`** (status 422); the
   `no_text_found` case passes its code per instance. The base `ConflictError` default code
   is `conflict`; both 409 codes are passed per instance.
9. **`PageTranscription` fields carry short `Field(description=...)` text** to steer the
   model; the schema is otherwise as planned (both fields required).
10. **Encrypted and corrupt PDFs both surface from pdfplumber as `PdfminerException`**
    (wrapping the pdfminer error), so `_read_text_layer` catches `Exception` around the open
    and the per-page extraction and maps it to `unreadable_document`. This is the plan's
    assumption in a concrete form; `pdfplumber` also pulls in `cryptography`, which pdfminer
    needs for encrypted files.
11. **The autogenerated migration was hand-formatted** to the style of `0002` (ruff format,
    `op.f(...)` names kept) and given revision id `0003`; `alembic check` reports no drift.
12. **Test layout.** Fixture builders are in `tests/modules/text_extraction/samples.py` and
    imported as `tests.modules.text_extraction.samples`; `conftest.py` holds the
    `make_document` fixture. Beyond the plan's list, tests also cover: no open DB transaction
    during vision calls, losing the upsert race, `force` switching method, transparent PNG
    flattening, an unparsed vision reply (`LLMError`), a blank-but-legible reply, and
    corrupt PNG / JPEG uploads.
13. **README not changed.** It does not list endpoints or setup that changed (the text
    route answers 409 until 0005 wires extraction, so there is nothing to demonstrate yet).
14. **NUL characters are stripped from page texts before saving (addition, from review).**
    Postgres `TEXT` rejects `\x00`, which broken PDF text layers or a model reply can contain;
    without this the insert would fail with a 500 instead of saving the readable text.
15. **The vision page-cap warning is logged in `_extract_pdf`**, not `_render_pages`: it is the
    caller that knows both the real page count and the cap.
16. **An unusable vision reply is detected with `isinstance(parsed, PageTranscription)`**
    rather than `parsed is None`, which also rejects a reply parsed into an unexpected type.

## Reason

Each choice is the smallest one that keeps behaviour correct and bounded (1, 3, 4), keeps
memory low (2), or follows from how the libraries really behave (10), without touching the
agreed API or data model.
